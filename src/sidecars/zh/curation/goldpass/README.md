## What gets verified

One verdict row per:

- **sliver tuple** (58) — word, pinyin reading, gloss sanity;
- **C9 context** (267) — the pinned function-word reading + tone-sandhi
  surface in its carrier sentence;
- **curated corpus sentence** (55) — naturalness, segmentation, readings.

Plus **planted-error rows** (≥3; wrong tone / wrong particle reading /
wrong citation) as rater-quality controls. Row ids in the committed sheet
are opaque and shuffled; the row→item mapping **and the planted-error answer
key live ONLY in the gitignored** `tmp/docs/zh-goldpass-answer-key.json`
(never committed — planted answers must not be publicly readable before the
pass; note the residual caveat that a determined rater could cross-reference
this public repo's assets to spot mismatching rows — accepted for this
protocol, and the agreement stats below back it up independently).

## Protocol

- **Raters:** 3 raters per item (every item, planted rows included).
- **Screener:** see `screener-spec.md` — native Mandarin speaker,
  Traditional-script literate (Taiwan/HK schooling or equivalent),
  pinyin-competent. Run the screener as a separate short Prolific study;
  only screener-passers get the main task.
- **Verdict per row:** 是 (correct) / 否 (wrong) + a free-text correction
  field (required when 否).
- **Rater quality gate:** a rater who misses any planted error (marks it 是)
  or whose pairwise agreement with the other raters falls below **κ ≥ 0.6**
  is excluded and replaced (their items re-collected). This mirrors the
  design §6.9 calibration bar (κ ≥ 0.8 tracks the *standing weekly* loop;
  the one-time gold pass uses per-rater exclusion + unanimity-or-adjudicate).
- **Item verdict:** 3/3 or 2/3 是 → PASS (2/3 flagged for review);
  otherwise the item is a **finding**: the tuple/context/sentence is
  corrected or dropped, the machine gate re-run, and the fix recorded.
- **Output:** run `process_results.py` on the exported CSV — it produces
  per-item verdicts, the rater-quality report, and the AC7
  provenance-record template to commit (checker provenance: platform,
  screener results, N raters, dates, cost — per the epic's cost note).

## Operator runbook (the only human steps)

1. Create/fund a Prolific account (budget note: 3 raters × ~340 rows ≈
   1,020 judgments; at the per-judgment rates in the epic's cost note this
   is a two-digit-USD study — confirm against the epic before dispatch).
2. Publish the **screener** study (`screener-spec.md`).
3. Publish the **main task** with `rater-instructions.md` as the description
   and `item-sheet.csv` as the task data (3 raters/item).
4. Export responses as CSV.
5. `python3 process_results.py responses.csv` (reads the gitignored answer
   key; writes `tmp/docs/zh-goldpass-report.md` + the provenance record
   template).
6. Commit the provenance record (NOT the answer key), tick AC7 on issue #20,
   and retire the GAPS.md row — that closes the issue.

## Regenerating the sheets

`item-sheet.csv` is generated by `make_item_sheets.py` from the committed
assets + corpus + gate results. Regenerate only with a fresh secret seed
(`--seed`), which re-shuffles row ids and re-plants the errors — then the
old answer key is invalid. Never commit the seed or the key.
